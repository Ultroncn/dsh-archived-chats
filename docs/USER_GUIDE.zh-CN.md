# 归档管理用户指南

[English](USER_GUIDE.md) · 简体中文 · [返回 README](../README.zh-CN.md)

归档管理为 DSH 已归档聊天提供查看和管理页面，并扩展按工作区批量归档。本文描述 2.0.1 的行为（包含未归档正文搜索），原生集成测试覆盖 DSH `0.1.7-rc.2`、`0.2.1-rc.2`、`0.2.1-rc.5` 和 `0.2.2-rc.1`。版本变更见[更新日志](../CHANGELOG.md)，接口和数据格式见[架构说明](ARCHITECTURE.md)。

归档管理优先复用宿主公开的 Modal、Button、Input、菜单、Tooltip 和图标组件。搜索框采用内置插件页面的 36px 高度、搜索图标和焦点样式，普通文本输入使用公开 Input。确认弹窗的标题、正文和操作区使用官方组件，复杂预览和导入内容使用官方弹窗框架；缺少相应导出的旧 Host 使用兼容样式。页面标题、说明、列表次要文字和焦点状态采用官方设置页的文字层级与主题变量。

## 会话状态与旧数据

| 位置 | 用途 | 如何返回主页面 |
| --- | --- | --- |
| 主页面会话区 | 日常继续聊天 | 已在主页面 |
| 已归档 | 保留聊天，但不在主页面会话区显示 | 点击「取消归档」 |

## 安装与打开

在 DSH 插件市场搜索 `dsh-archived-chats`，核对作者为 **Ultronen** 后点击「安装」。安装完成后按宿主提示重启 DSH，打开 **设置 → 归档管理**。

也可以在运行 DSH 的主机上使用命令行安装。以下以 `web` profile 为例，请替换为实际运行 DSH 的 profile；更新和卸载也使用同一 profile：

```sh
dsh plugin --profile web add dsh-archived-chats@latest
```

若安装报错 `ERR_PNPM_ADDING_TO_ROOT`，说明该 profile 是 pnpm workspace 根目录。请加上 `-w` 重试，并替换为实际 profile：

```sh
dsh plugin --profile web add -w dsh-archived-chats@latest
```

如果设置入口未出现，请核对插件是否安装并启用在实际运行 DSH 的 profile 中，重新加载宿主，并检查[兼容性要求](#兼容性与限制)。

旧版用户更新前，请先阅读下方「升级、旧数据与降级」，尤其是旧快照清理说明。

## 第一次使用：找回并备份一条聊天

1. 打开 **已归档**，输入记得的关键词。如果列表为空，先用 DSH 的会话菜单归档一条已结束的聊天。
2. 点击聊天标题预览对话，确认内容后关闭预览。
3. 点击 **选择**，勾选需要保留的聊天，再选 **导出选中**（窄面板中位于 **更多**），核对选中数量并确认。
4. 在浏览器下载中确认 ZIP 已保存；ZIP 不包含附件文件，需要另行保留。

搜索边界见[归档与查找](#归档与查找)，备份限制与恢复方式见[导出和导入](#导出和导入)。

## 归档与查找

单条聊天仍使用 DSH 原有会话菜单归档。归档后的提示与撤销操作由 Host 自己提供，插件不再额外弹出提示或替换官方归档方法。归档后的聊天在插件中按工作区分组。

已归档和未归档的「所有工作区」菜单使用文件夹图标列出工作区，并提供「未分组」与「自动化任务」入口。未分组按官方工作区成员关系判断，不按标题或旧目录推测。自动化任务通过官方 `schedule.catalog()` 的会话关联筛选，覆盖仍保留记录的活动及已结束任务；任务被删除后不再匹配，不能把它当作永久的历史会话类型。宿主未启用该服务或读取失败时，入口置灰并提供原因，不影响普通会话列表。

已归档、未归档采用两排工具栏：搜索框独占第一排，筛选控件位于第二排。来源与分支的搜索框独占第一排，工作区与状态筛选、会话数量和全部展开／折叠合并在第二排，窄屏按需换行。

已归档和未归档默认按「最近更新」排序，与官方首页一致：以创建时间和最后一次用户发消息时间中的较晚者为准。「最早更新」反向排列；也可按标题排序。助手输出、标签和备注修改不影响该排序。宿主缺少对应时间数据时回退到创建时间；聊天行显示的日期仍为创建时间。

在 **未归档** 中，顶部搜索框独占一排，下一排的第一个筛选菜单与已归档一致，包含「类型」和「排序方式」。类型可选全部聊天、普通会话或子代理会话，两个页面分别保留类型选择，正文搜索也遵循当前类型筛选。旁边可筛选工作区。右上角的 **刷新** 文字按钮重新加载列表，与 **全部归档** 并列。列表与已归档使用相同的工作区分组及会话行排版。

- 单条聊天点击标题只读预览内容，或点击带图标的「归档」。
- 工作区三个点菜单中的「全部归档」覆盖该工作区。
- 顶部「全部归档」覆盖列表中的所有工作区。

未归档列表的工作区更多菜单提供「全部删除」，确认时显示该工作区的全部未归档聊天数量，搜索不会缩小范围。操作统一检查会话身份、工作区归属和运行状态，并计入关联子智能体，成功与失败分别报告。

搜索和工作区筛选只改变显示，不缩小工作区或全局归档范围。操作会先检查实际可归档范围；普通单条会话直接归档，不弹出确认。归档主页当前显示的会话时，归档管理保持打开，并显示服务端确认后的成功提示。用户可主动关闭设置。全局和工作区批量归档仍需确认：全局说明所有工作区，工作区保留名称，不显示数量。未归档展示所有已登记工作区及「未分组」中的已有聊天；列表与批量归档统一排除已归档、待删除及子代理会话，执行期间再次检查资格；排除已确认的空白新建聊天；暂时无法读取内容的聊天仍显示，但暂不可归档。正在运行的聊天可以点击归档：确认窗口提示「停止并归档」，确认后调用官方停止并归档能力。批量归档包含运行中的聊天时也会明确提示停止工作；空白或内容无法确认的聊天不能归档。准备后新增的聊天不纳入此次操作；确认期间才开始运行、未经停止确认的聊天以及改变工作区的聊天会跳过。未归档提供只读预览、归档、单条删除及工作区全部删除，不提供勾选、导出或「可清理」入口。归档不更改工作区目录，保留已有标签和备注。取消归档使用官方接口；插件订阅官方工作区状态变化，首页或其他页面的归档操作会同步更新已归档和未归档列表。官方重命名也会同步更新列表标题；未归档列表后台刷新时保留已有条目，首次加载显示「正在加载会话…」。旧 Host 缺少官方停止或取消归档能力时会明确报错，不改写官方状态来模拟。

确认归档后，全部成功会关闭弹窗，使用 Host 原生提示组件显示「归档成功，已归档 N 个会话」和「查看已归档」入口，数量以实际归档结果为准。没有原生提示组件的旧版 Host 会保留结果窗口。有跳过或失败时保留详细结果，不显示全部成功提示。

「已归档」和「未归档」均可搜索标题、会话 ID、工作区、标签、备注、消息和工具结果。两个页面各自搜索：已归档只搜索已归档，未归档只搜索未归档。结果和管理操作始终属于当前页面。每次检索或预览重新读取运行中会话，搜索结果不会随流式输出持续更新。已归档页可按类型、工作区、标签筛选，并按时间或标题排序。正文命中会显示摘要；工作区长标题自动换行、完整显示。点击工作区标题行可展开／收起聊天；平时显示文件夹，仅悬停时切换为指示展开状态的实心三角，并高亮整行；移开鼠标恢复文件夹，只有菜单打开期间保留整行背景。分组折叠状态保存在浏览器中。

正文搜索在去除首尾空白后的关键词至少有两个 Unicode 字符时开始。工作区、类型和标签筛选先确定候选范围，客户端每批搜索 20 个候选，API 每次最多接受 100 个明确候选 ID。结果逐步区分已处理候选／总数、正文命中聊天数、当前显示聊天数和失败聊天数。当前显示包含元数据或正文命中的聊天，同一聊天只计一次；这些数量统计聊天而非摘要条数。搜索完成表示已在投影范围内扫描所选候选，不存在 100 个正文命中的总上限；每个命中聊天最多展示三条摘要。更短的关键词仍按列表数据匹配标题、工作区、标签和备注。两个列表采用相同的搜索规则。

「停止搜索」保留已经找到的结果；「重试未完成项」重试未读取及尚未处理的候选，不重复成功命中。读取失败会显示受影响 ID 和原因；网络失败会停止后续批次并保留之前的结果。已移除或变为不可见的候选会标为跳过，不会自动扩大检索范围。更改关键词、筛选条件、会话列表或页面会取消旧检索并丢弃迟到响应。

搜索和预览使用有资源上限的投影，并非无限制原始日志索引：最多 10,000 条投影消息，每条最多 1,000 个片段，每片段最多 256 Ki Unicode 码点，每条消息最多 1 Mi 码点。因此超长日志或内容块可能存在投影范围外的文本，未命中不等于原日志没有匹配内容。

## 预览、标签与备注

无需取消归档即可只读预览对话。支持 Markdown、思考、代码、JSON、工具调用和结果，以及可以读取的已存储图片。没有附件读取能力时，只降级图片；关闭预览会取消未完成请求。

完整加载且有结束记录的轮次，将中间过程归入默认收起的过程折叠项。摘要显示「已思考」或日志中记录的工具、消息、子代理数量；展开后可查看分层的思考、上下文来源、工具摘要及参数和结果，这些详情也默认收起。最终回复独立显示在过程之外。未完整加载或缺少可靠轮次边界的内容保持展开，按事件顺序展示，不强行合并成完整轮次。

系统提示词默认收起，展开后在限高区域内滚动。会话恢复或开启新请求系列时，按记录展示当轮生效的系统提示词；信息不全时不推测。只有真实用户消息显示在右侧；AI 处理过程、思考、工具和注入上下文都在左侧。预览不提供输入框，有宿主 Markdown 渲染器时优先使用；不承诺完整复刻原生会话的所有功能或展示日志中缺失的信息，也不编造用量和耗时。

更新后需要重新加载 DSH 后端才能启用新版预览投影，仅刷新浏览器不会替换正在运行的后端。

点击预览窗口右上角的「编辑标签与备注」图标进行编辑。每条聊天最多 8 个标签，每个标签最多 24 个 Unicode 字符，备注最多 2,000 个 Unicode 字符。标签匹配不区分大小写。列表中备注为单行，截断时可悬停或聚焦查看完整内容。

标签和备注只保存在本机。取消归档不会清除它们；完成永久删除后会清理。

## 操作入口与范围

| 页面与入口 | 可用操作 | 范围 |
| --- | --- | --- |
| 已归档：单条聊天 | 行内为垃圾桶图标（永久删除）、取消归档；点击标题预览，预览右上角直接提供编辑标签备注图标，不提供删除 | 当前聊天 |
| 已归档：工作区「更多」 | 该工作区：全部取消归档、全部导出；分隔线；全部删除 | 该工作区的全部已归档聊天 |
| 未归档：聊天行 | 点击标题预览、归档、永久删除 | 单条聊天；直接归档，正在执行时确认停止 |
| 未归档：工作区三个点菜单 | 该工作区：全部归档、全部删除 | 归档针对可归档聊天；删除针对该工作区全部未归档聊天，并计入关联子智能体 |
| 未归档：顶部 | 全部归档 | 所有工作区的可归档聊天 |
| 已归档：顶部 | 选择、三点更多 | 进入选择模式或打开全局操作菜单 |
| 已归档：选择模式 | 全选、取消归档、导出选中、垃圾桶图标（永久删除）、取消 | 操作仅针对勾选聊天；全选仅针对当前结果 |
| 已归档：顶部「更多」 | 导入备份、全部导出、全部取消归档；分隔线；全部删除 | 导出、取消归档及删除覆盖所有工作区的已归档聊天；导入使用所选 ZIP |

**选择模式支持单条和多条操作。** 点击「选择」显示复选框和操作栏，行内隐藏操作按钮，点击标题仍可预览；取消归档、导出选中、垃圾桶图标（永久删除）和取消依次直接展示；空间不足时，导出选中收进三点「更多」。未选中会话时，操作按钮禁用，取消仍可用。「全选」勾选当前搜索／筛选结果，部分勾选时显示半选；隐藏的已选项保留并显示数量。取消当前结果的全选不会取消隐藏选择。「取消」或离开已归档会退出模式并清空选择。执行前确认选中数量，失败项保留勾选。普通列表右侧仅保留垃圾桶图标（永久删除）和「取消归档」；点击标题后，预览窗口右上角直接提供「编辑标签与备注」图标，不提供删除或更多菜单；未归档提供只读预览和归档操作。工作区和顶部批量操作不会因搜索、筛选隐藏了部分聊天而缩小范围。

「降级」表示保护数据不可用或不完整，不一定表示聊天无法恢复：原会话仍存在时仍可能恢复。工作区全部恢复会尝试非待删除条目，并报告失败原因；已进入永久删除流程的条目不能恢复。

## 永久删除与失败重试

删除需明确确认，成功后无法恢复。已归档和未归档使用相同规则，删除所选会话及其子智能体后代，普通分叉独立保留。单条、工作区和全局操作先计算范围，确认弹窗显示所选会话数、额外关联子智能体数和总数。范围读取完成前禁用确认按钮。

**删除的数据范围**

- 删除每个目标会话经验证独占的存储目录，包括会话日志及该目录内的文件；同时清理对应的工作区成员关系、归档记录、Host 会话索引、插件标签备注和来源追踪记录。
- 子智能体后代按真实父子关系递归纳入，可能具有不同的工作区或归档状态。普通分叉仅在自身被选中时纳入。
- 工作区目录、项目代码、Git 仓库与工作树、会话目录之外的全局共享附件和缓存、另行导出的 ZIP 及其他独立备份均保留。会话目录内的文件随目录一起删除。

删除前如需保留内容，请先导出目标会话及需要保留的子智能体；未归档会话需先归档再导出。插件 ZIP 不包含附件二进制，也不会自动打包后代会话，附件需另行备份。

全部目标必须空闲。确认后会重新核对身份、归档状态、工作区及删除范围；范围变化时要求重新确认。失败重试沿用持久保存的会话身份和确认范围，历史仅删选中项的任务保留原范围。

删除失败时，错误提示提供「重试」，继续已确认的删除范围。重新打开管理页或刷新后，未完成的删除也会显示重试提示。操作由用户点击触发。界面固定为已归档、未归档、来源与分支、关于四个标签。

删除任务保存于 `plugin-data/archived-chats/deletion-tasks.json`。升级会承接已确认的待删除任务；旧恢复记录和保护快照留在磁盘，当前界面已移除其操作入口。

## 导出和导入

每个 ZIP 包含：

```text
manifest.json
sessions/001-<安全标题>-<id>/session.json
sessions/001-<安全标题>-<id>/transcript.md
```

JSON 是机器可读记录，Markdown 是可读副本。新版 Host 导出 ZIP v2，保留分叉会话的精确继承边界；旧读取接口仍导出 v1。两者都保留附件引用，但**不包含附件二进制，也不会自动打包后代会话**；不等于完整附件备份。需要完整会话树时，可查看 Harness 官方 Session log 导出能力。

返回下载流之前，导出会仅读取每个选中来源一次，暂存渲染后的 manifest／会话／Markdown 条目，并执行与导入相同的完整格式和语义验证。因此，本插件成功导出的备份会符合本插件导入器的格式与大小预算。任一来源无效或超限时，整个导出会在成功下载响应前被拒绝，不会产生不完整备份。

共用限制为：最多 2,000 条会话、4,001 个条目；`manifest.json` 和每个会话 JSON 各 4 MiB；任一 ZIP 条目和每个 Markdown 文本各 8 MiB；解压后总量 256 MiB。导入 ZIP 的压缩输入上限为 512 MiB。每个 JSON 还限制深度 64、节点 100,000 个，其所有字符串合计最多 4 Mi Unicode 码点。JavaScript 字符串实际占用的内存可超过编码字节总量。

导入接受本插件 v1 和 v2 ZIP，先预览再确认写入：

- 已存在的会话 ID 和未完成删除任务均标为冲突、禁用并跳过，不覆盖原会话。
- 缺少对应工作区时，带警告导入为未分组归档聊天。
- 与当前系统不兼容或有歧义的工作目录会在预览中禁选，写入前再次拒绝，不自动转换或丢弃。例如 macOS/Linux 上的 Windows 盘符路径，以及 Windows 上的 `/project` 一类根路径。后者可能来自 POSIX，也可能是 Windows 当前盘符根路径，现有备份无法区分，因此保守拒绝。无效和盘符相对路径也会被拒绝。请保留原 ZIP；当前版本不提供本地目录映射，这不是完整的跨平台迁移功能。
- 标签和备注遵守相同长度限制。
- 确认过期后需要重新预览；缺少恢复写入能力时拒绝执行。

导入后会话回到「已归档」，保留原 ID、标题、事件及标签备注；先预览确认，再「取消归档」回到主聊天列表。新版 Host 导入会明确持久化并释放写入占用。若写入失败后残留文件的归属无法确认，会明确提示回滚未完成并保留文件；请保留 ZIP，排查后再重试，不要为消除冲突而直接删除已有聊天。

导入要求 ZIP 完整且内部一致，会拒绝截断、CRC 或本地／中央目录不一致、无效 UTF-8、不安全路径或 JSON 键、重复／未引用条目、加密、ZIP64、多磁盘归档，以及 Store／Deflate 之外的压缩方式。普通 v1 备份仍受支持，但没有精确继承边界的 seeded v1 来源会被拒绝，不会被展平。

浏览器会在发起下载前缓冲并验证完整 ZIP。响应字节上限为 320 MiB，完整获取／读取响应体的超时为五分钟；这不是峰值堆内存保证，当前非流式兼容路径也没有更强的通用 WebView 内存承诺。“已开始下载”不表示浏览器已将文件保存到磁盘。超时或超限时不会下载不完整文件，可重试。

导出按 256 KiB 分片压缩已暂存的条目，并在分片之间让出事件循环，因此生成大型备份时不会长时间占用 Host 主线程。下载被取消时归档立即停止且响应失败，已取消的导出不会被报告为完成。

未归档列表中的垃圾桶按钮可发起永久删除，确认框显示聊天名称、关联子智能体数量和不可恢复提示。运行中的目标需先在官方界面停止。服务端重新检查未归档状态、身份、工作区和确认范围，并通过统一删除流程执行。失败后可在错误提示中重试。

## 来源与分支

会话范围说明收起到会话数量旁的提示图标；将鼠标放上去、用键盘聚焦或触屏点击即可查看。

会话按实际所属工作区展示紧凑列表，工作区标题显示数量，折叠状态保存在浏览器。每行展示标题、归档状态、直接来源、分支数量、创建时间和会话 ID，并可复制完整 ID；未分组聊天有独立分组。同一会话只在所属工作区列出一次，来源参考不重复计数。

工作区顺序与主页面一致，组内会话默认按最近更新时间倒序排列。主页面使用手动排序时，列表沿用其已保存的顺序；缺少更新时间的历史记录按创建时间排序。

点击「会话谱系」打开「会话谱系图」大弹窗，展示该会话所在的完整关系树，包括跨工作区的祖先、同源分支及后续分支，并定位、高亮当前会话。列表中的搜索、工作区和状态筛选不会裁剪弹窗中的关系树。没有关联的会话标为「独立会话」，不显示关系图入口。若会话包含继承的历史但未记录父会话，则显示「未记录来源会话」；这不代表正文丢失，仍可点击标题预览。

图内节点直接展示标题、状态、工作区、来源、创建时间和复制 ID，所有分支直接可见，无须展开卡片。普通分支用实线曲线，子智能体用虚线；只连接真实父子关系。按住空白区域可自由拖动画布，普通滚轮平移，Ctrl／⌘ 加滚轮围绕鼠标位置缩放。右下角提供放大、缩小和「适应窗口」，左下角显示节点与关系数量。「适应窗口」会按当前可用空间缩放并居中整张图，保留外边距，最大放大到 200%。按 Escape 或右上角关闭图标关闭关系图，保留列表搜索、筛选、折叠和滚动位置。

搜索框提示「搜索会话标题、工作区和 ID」，独占第一排；工作区与状态筛选、会话数量、范围说明入口和全部展开／折叠合并在第二排，窄屏按需换行。搜索临时展开匹配工作区，清空后恢复折叠状态。「全部展开／折叠」仅作用于当前结果的工作区。搜索结果标明直接匹配及相关分支；保留的来源参考不代表自身匹配关键词。

列表及图内标题均可打开只读预览。图内点击卡片空白高亮来源路径，复制 ID 独立操作；关闭预览后保留画布缩放和浏览位置。来源不可用时不提供预览入口。信息不足时显示「来源待确认」，不推断为原始会话或已删除。

## 关于与更新

从 1.4.1 起，仅确认有新版本时，「关于」标签右上角显示红点；尚未检查、检查失败或已是最新版时不显示。打开「关于」不会清除仍可用的新版本提示。

官方侧栏的归档成功提示追加「查看」按钮，点击后打开「归档管理 → 已归档」并刷新列表。

「关于」展示产品说明与项目信息、版本与更新。保留当前版本、作者、许可证，以及项目主页、对应语言的使用指南、更新日志、问题反馈和插件市场链接。页面标题旁也显示当前运行版本。

「当前版本」动态读取正在运行的后端，不使用网上最新版代替。联网检查失败不会清除已读取的版本、作者或链接；本地信息读取失败则显示「暂不可用」和「重新读取」，不误报为检查更新失败。若刚更新插件但新接口尚未加载，请重新加载 DSH 后端后重试。

打开归档管理时先读取本地信息，再自动查询公开 npm 版本；页面保持打开时每 15 分钟进行缓存感知检查，重新显示或联网时也会补查。成功结果缓存 12 小时，失败结果缓存 15 分钟；手动检查使用 30 秒短限流，并发请求合并。只查询公开版本，不发送聊天或备份内容；失败不阻塞会话管理，也不显示「已是最新版」。关闭页面会清理定时器和事件监听。

更新后版本未变化时，还应核对更新的 profile 是否就是实际运行 DSH 的 profile。

「检查更新」与标题旁的「查看更新」打开更新弹窗，展示运行版本、公开版本、上次检查和当前环境。支持复制包名到另一端的「添加插件」；命令只在能验证当前启动程序和 profile 时提供，官方桌面端使用其自带命令，不依赖 PATH 中的另一套 dsh。这里只识别当前环境，不扫描或自动安装到其他桌面端。

本地 `link:` / `file:` 等来源标记为「本地开发版」，提供复制本地路径，后端拒绝用线上包覆盖。npm 安装在宿主支持时提供「安装更新」，优先调用官方 `updateBundle`，由宿主检查版本与兼容性、替换旧插件，并在安装失败时尝试恢复旧版本。更新期间设置页可能关闭，完成后重新打开归档管理核对运行版本。结果区分「宿主已应用」和「需要重启」；旧版恢复成功或未能确认恢复均有明确提示。旧 Host 缺少更新接口时，仅在允许替换的环境使用官方安装接口，其余引导前往官方插件页的版本区域更新。重复提交被阻止，DSH 重启由用户操作。

## 升级

升级保留已有归档、标签备注及待完成删除任务。旧恢复记录和保护快照文件留在磁盘，当前版本不再提供旧恢复操作。Host 兼容范围由包声明与原生集成测试确定。

## 兼容性与限制

- **设置弹窗自动关闭（宿主已知问题）：** DSH `0.2.1-rc.2` 在首次配置未完成时，归档当前聊天可能触发引导并关闭设置。此问题已反馈至官方 [#10596](https://github.com/deepseek-ai/deepseek-harness/discussions/10596)，不代表归档失败；可重新打开设置核对结果。本插件 1.6.0 不包含宿主修复。

功能取决于 Host 公开能力，不仅取决于版本号：

声明的 DSH `>=0.1.0-rc.7 || 0.2.2-rc.1` 范围仍表达基于 Host 公开能力的兼容性。发布自动化在 Ubuntu 上测试 Node.js 18，并在 Ubuntu、macOS 和 Windows 上测试 Node.js 24；Node.js 24 矩阵强制运行官方 `@deepseek-ai/dsh-session@0.1.7-rc.2`、`0.2.1-rc.2`、`0.2.1-rc.5` 和 `0.2.2-rc.1` 四套锁定 Host 后端集成（各 9 项）与打包检查，覆盖 v4 会话格式。

## 本地数据与卸载

插件状态位于：

```text
$DSH_HOME/plugin-data/archived-chats/
```

| 文件 | 用途 |
| --- | --- |
| `metadata.json` | 标签和备注 |
| `pending-deletions.json`（旧版遗留） | 旧删除标记迁移输入 |
| `deletion-tasks.json` | 待完成永久删除任务 |

插件不会上传、云同步或定时抓取历史版本。卸载命令：

```sh
dsh plugin --profile web remove dsh-archived-chats
```
